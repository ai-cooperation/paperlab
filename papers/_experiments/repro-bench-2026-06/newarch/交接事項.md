# Paper Lab V3.2 交接事項

日期：2026-07-02

## 一句話狀態

目前 V3.2 已經把「不會卡死」往前推進，但 `review_heal` 被 harness 補太多，允許 deterministic review 補出 pass，這偏離 Hermes+Skill engine 的 loop 設計。下一輪要先修回「Hermes 自主理解目標、選 skill、執行專家審查、留下可驗證 provenance」，再談 production pass。

## Spec 對齊基準

依據 `V3_2_SPEC.md`，核心原則是：

- Harness owns boundaries.
- Loop owns progress.
- Validators own truth.
- State owns continuity.
- Humans own high-decision-cost judgment.

對 `review_heal` 而言，合理分工應是：

| 層 | 正確責任 |
|---|---|
| Harness | 提供 skill registry、VIP capability、runtime sandbox、expected outputs、timeout、candidate snapshot |
| Hermes loop | 理解「domain expert review」目標，主動選擇適合 reviewer skill，執行審查與修復迴圈 |
| Validator / Gate R | 驗證 review artifact 是否可信、完整、可追溯；不能替 Hermes 宣稱已審查 |
| State | 保存 skill decision trace、review JSON/log、candidate manifests、repair history |

不能再把 deterministic schema completion 當作專家審查通過。這違反 `V3_2_SPEC.md` 的「Do not use harness repairs to compensate for an underspecified loop」。

## 已驗證事實

### 1. reviewer skill 有被放入 Hermes skill context

`engine_v3/packs/paper.py` 的 `PAPER_SKILL_BUNDLE` 包含：

- `paper-review-skill`
- `elite-reviewer-audit`
- `paper-logic-audit`
- `figure-table-checker`
- `pdf`

遠端 job 的 `engine_v3_skill_context.md` 也能 grep 到 `paper-review-skill` 與 Phase 9 quality review 相關文字。

結論：目前不是「skill 完全沒載入」。

### 2. 但 production review artifacts 不是 Hermes reviewer skill 產物

抽查 4 個已重跑 job：

- `v3_0f6a0c83f9cf`
- `v3_e0647ab06a6f`
- `v3_03d8e9b50bfc`
- `v3_11c16e4b8735`

四個 `quality_review_round1.json` 都顯示：

```json
{
  "reviewer": "deterministic bounded final review",
  "review_loop": {
    "reviewer_model": "deterministic bounded final review",
    "fixer_model": "deterministic structural repair"
  },
  "review_method": {}
}
```

四個 `quality_review_log.md` 都顯示：

```text
Reviewer: deterministic bounded final review.
This review is deterministic and artifact-bounded; it does not add external evidence.
```

結論：目前 pass 的 review 不是 VIP domain expert review。

### 3. Gate R 目前驗收條件太弱

`engine_v3/packs/paper.py::_review_loop_ok` 目前只檢查：

- status pass-like
- rounds >= 1
- reviewer_model 非空
- reviewer_model 不含 `fallback`
- fixer_model 非空
- independent_reviewer true
- floor_failed false

因此 `deterministic bounded final review` 不含 `fallback`，會被當成合法 reviewer 放行。

### 4. 問題不是「要強制 Hermes 用某個 skill」

正確設計不是 harness 硬指定 Hermes 必須用 `paper-review-skill`。正確設計是：

1. Harness 提供 capability registry 與 VIP 權限資訊。
2. Hermes 根據任務目標主動選擇 reviewer capability。
3. Hermes 必須留下 skill decision trace。
4. Gate R 驗證「真的有 loop decision + review execution provenance」。
5. 若 Hermes 沒有選 skill、VIP capability 不可用、或 review artifact 沒 provenance，應 blocked/revise，不可 deterministic pass。

## 目前偏差

### 偏差 A：Harness 補出 pass review

`engine_v3/pipelines/paper.py` 內 `_ensure_review_record_v3_2` 會在 review 缺失或不完整時補出：

- `reviewer = deterministic bounded final review`
- `delivery = pass`
- `p0_count = 0`
- 7 個 dimension score
- `independent_reviewer = true`

這讓 deterministic repair 從「schema 補齊」越界成「專家審查結論」。

### 偏差 B：review_heal prompt 要求 artifact schema，但沒有要求 skill decision trace

目前 `REVIEW_HEAL_PROMPT` 要求七維度、findings、delivery、floor，但沒有要求 Hermes 說明：

- 看見哪些可用 review capabilities
- 為何選某個 reviewer skill
- 是否因 VIP 權限啟用 domain expert review
- 檢查了哪些 input artifacts
- 哪些 findings 被修復、哪些保留

結果是 artifact 欄位完整，但無法證明 Hermes loop 真的運作。

### 偏差 C：Gate R 驗欄位，不驗 provenance

Gate R 應驗證「審查來源與 loop 行為」，不是只驗 JSON 欄位完整。

## 待辦

### P0：停止 deterministic review pass 旁路

- `_ensure_review_record_v3_2` 不得產出 pass-like review。
- deterministic 補齊只能產出 `delivery = revise` 或 `blocked_revise`。
- 如果 Hermes 沒有產出可信 review artifact，Gate R 必須 blocked。

測試要求：

- 缺 review JSON 時不可被 deterministic 補成 pass。
- `reviewer_model = deterministic bounded final review` 時 Gate R fail。
- deterministic review 可以作為診斷 artifact，但不可讓 final delivery pass。

### P0：加入 review capability decision trace

新增 review artifact contract，例如：

```json
{
  "review_method": {
    "schema_version": "paperlab.review_method.v3.2",
    "decision_owner": "hermes",
    "capability_class": "domain_expert_review",
    "selected_skill": "paper-review-skill",
    "selection_reason": "The task asks for domain expert review before delivery.",
    "vip_capability_required": true,
    "vip_capability_available": true,
    "inputs_checked": [
      "paper_draft_v0.qmd",
      "paper_springer.pdf",
      "references.bib",
      "claim_evidence_map.md",
      "real_experiments/real_results.json",
      "doi_audit.json",
      "render logs"
    ]
  }
}
```

注意：Gate 不應只允許單一 hard-coded skill id。Gate 應驗證 selected capability 屬於可用 reviewer capability，且 artifact 符合 expert review contract。

### P0：Gate R 改為驗 loop provenance

Gate R 必須 fail closed：

- `review_method` 缺失 -> fail
- `decision_owner != hermes` -> fail
- `capability_class != domain_expert_review` -> fail
- `vip_capability_required = true` 但 `vip_capability_available != true` -> blocked
- `reviewer_model` 含 deterministic/fallback/schema completion -> fail
- `quality_review_log.md` 沒有 skill decision trace -> fail
- findings 為空時，必須有七維度逐項「已檢查且無 P0/P1」的 rationale

### P1：review_heal prompt 改成目標導向，不硬塞 skill

Prompt 應表達：

- 你是 Hermes review_heal loop。
- 目標是判斷論文是否達到 VIP/domain expert review delivery quality。
- 你可以使用 skill registry 中的 capabilities。
- 你必須先根據目標選擇適合 review capability，並記錄 decision trace。
- 如果沒有可用 capability，不可假裝完成，必須 blocked。

避免寫成「必須使用 `paper-review-skill`」。那會把 loop decision 又塞回 harness。

### P1：candidate manifest 記錄 skill invocation

每次 review_heal runtime attempt 應保存：

- 可見 skill registry 摘要
- Hermes selected skill
- selection reason
- review input list
- output artifacts
- blocked reason 或 pass reason

這對應 `V3_2_SPEC.md` 的「Skills are capabilities, not proof」。

### P1：批量驗證

修完後重跑至少：

- 上述 4 個舊 job
- 3 個 V3.2/V3.1 revalidation topic
- 1 個 b-side -> a-side 新 contract

每個 job 必查：

- status page 非卡死
- `quality_review_round1.json` 有 `review_method`
- `quality_review_log.md` 有 Hermes skill decision trace
- Gate R 沒有 deterministic pass
- PDF 目視檢查：引用是藍色超連結、章節編號正確、表格寬度正常、無內容填充 boilerplate

## 成功定義

這次不能只說「blocked 是正確的」。成功必須同時滿足：

1. 不會卡死：job 能到 `done_pass` 或精確 blocked/human checkpoint，狀態頁可讀。
2. 不假通過：沒有 Hermes domain expert review provenance 時，不能 pass。
3. 會修到 pass：可修問題要經 Hermes loop 修復，不能停在永久 blocked。
4. PDF 合格：章節編號、引用超連結、表格寬度、圖表引用、內容品質都通過目視與機械檢查。
5. 批量驗證：多個舊 job 與新 contract 都能跑出一致結果。
