# Post-Generation Paper Assessment and Sequenced Correction Plan

This document contains a detailed assessment of the HUPD patent ML paper generated by the Hermes CLI pipeline and outlines a sequenced plan to fix journal formatting deficiencies and introduce an automated review-revision iteration loop.

---

## A. Paper Review & Formatting Deficiencies

The generated paper, *"A Reproducible CPU-Only Classical ML Benchmark for HUPD Patent Acceptance Prediction"* (`paper_draft_v0.qmd`), has an overall quality score of **6.64 / 10.0** (based on `final_content_review_deterministic.json`). While the literature grounding (7.5) and writing coherence (7.5) are rated highly, the paper is blocked from completion due to a **P0 methodological contradiction** (G2-001) and several formatting deficiencies when compared to a publication-ready **Scientometrics (Springer)** manuscript.

### 1. The P0 Methodological Contradiction (G2-001)
- **The Defect**: The paper asserts a "fail-closed" temporal holdout split.
  - In **§3.1 (Data: HUPD Corpus and Preprocessing)**: *"Our sample consists of 2,000 utility patent applications with a filing year of 2016."*
  - In **§3.3 (Evaluation Protocol)**: *"The fail-closed design ensures that temporal holdout (training on 2014–2018 applications, evaluating on 2020 applications) prevents future-data leakage."*
  - In **Limitations**: Reference to *"the temporal holdout design (single filing year 2016)"*.
- **The Contradiction**: A temporal holdout split (training on 2014-2018, testing on 2020) is logically and mathematically impossible when 100% of the underlying sample data is from a single filing year (2016). The actual experiment performed was a nested 5-fold cross-validation on 2016 data, but the prose misrepresents it.

### 2. Specific Formatting Deficiencies vs. Scientometrics (Springer)
The PDF produced by the ReportLab fallback renderer (`paper_draft_v0.pdf`) exhibits major formatting flaws:
- **Title Block (Ignored Frontmatter)**: The renderer completely ignores the YAML frontmatter of the QMD. It prints the string `"paper_draft_v0"` as the title. It fails to output the author name (`"Cooperation.TW"`), affiliation (`"Paper Lab"`), email (`"aicooperation.tw@gmail.com"`), or publication date. Springer requires a centered title, full author names, numbered affiliation listings, and a corresponding author email footnote.
- **Abstract & Keywords Layout**: The abstract is treated as a standard section with a regular heading and standard paragraph style. In Springer format, the abstract must be indented on both sides (typically 0.5 inches), set in a smaller font (e.g., 8.5pt/11pt leading), and followed immediately by a bolded list of keywords (e.g., *Keywords: Patent analytics, HUPD, Reproducibility...*).
- **Section Numbering**: The document headings (`# Introduction`, `# Related Work`) are rendered as plain text. Springer style mandates decimal section numbering (e.g., `1 Introduction`, `2 Related Work`, `3 Methodology`, `3.1 Data: HUPD...`).
- **Citations In-text**: The PDF renders raw markdown citations like `[@Lanjouw2004]` and `[@Hall2001]` as plain text. A proper Springer basic manuscript must resolve these to Author-Year style (e.g., `(Lanjouw and Schankerman, 2004)` or `Lanjouw and Schankerman (2004)`).
- **Bibliography Section**: The `# References` heading is rendered, but the section remains completely empty. Because the reportlab fallback doesn't read `references.bib`, no bibliography list is compiled or appended. Springer requires an alphabetical, hanging-indented reference list at the end of the document.
- **Figures & Captions**: The markdown alt-text and labels (e.g., `{#fig-cpc-distribution}`) are dropped by the renderer. Figures are placed inline without a label or caption (e.g., `Fig. 1 CPC section...` is missing).
- **Tables Layout**: Tables are rendered as monospaced preformatted code blocks inside a `Preformatted` flowable, which breaks page margins and alignment. Springer requires centered tables with a bold caption *above* the table (e.g., `Table 1 Characteristics...`) and a clean booktabs-style grid (no vertical lines, thick top/bottom lines, and a thin line separating headers from data).

## B. Fix 1 — Journal Format

### 1. Concrete Recommendation & Tradeoffs
We recommend **Option (ii): Build an enhanced, Springer-style ReportLab template** by modifying the existing fallback renderer `render_qmd_reportlab.py`.

#### Options Analyzed:
- **Option (i): Install Quarto + TinyTeX/TeXLive on `ac-2012`**
  - *Pros*: Native support for Springer LaTeX template rendering, automatic citation and table processing.
  - *Cons*: High deployment risk. `ac-2012` is a container environment with restricted permissions (likely no root/sudo) and potentially no internet access, making multi-gigabyte TeX packages or third-party CLI binaries highly prone to failure.
- **Option (ii): Enhance ReportLab fallback template**
  - *Pros*: Zero external dependencies. ReportLab is already installed on `ac-2012` and verified working. Execution is instant and 100% reliable inside the Python sandbox.
  - *Cons*: Requires custom Python regex/string parsers for YAML, BibTeX, inline citations, and markdown tables.
- **Option (iii): Render on external Quarto host**
  - *Pros*: Outsources rendering weight.
  - *Cons*: Introduces networking overhead, SSH credential dependencies, and API exposure risks. Breaks the self-contained container environment contract.

### 2. Implementation Steps for Option (ii)
We will modify `/Users/user/projects/ai-paper-workshop/papers/_experiments/repro-bench-2026-06/render_qmd_reportlab.py` to add the following features:

1. **YAML Frontmatter Parser**: Parse the text block between the first two `---` markers. Extract `title`, `author` details, `date`, and dynamically inject `keywords` (to be specified in YAML).
2. **BibTeX Parser**: Create a simple parser to scan `references.bib`. Build a dictionary mapping citation keys to their formatted author list and publication year:
   - Extract the `author` and `year` fields.
   - If 1 author: `Lastname`.
   - If 2 authors: `Lastname1 and Lastname2`.
   - If 3+ authors: `Lastname1 et al.`.
3. **Citation Replacer**: Search the body text for parenthetical citations `\[@([^\]]+)\]` and replace them with formatted citation strings (e.g., `(Lanjouw and Schankerman, 2004)`). If multiple keys are grouped, format them as `(Author1, Year1; Author2, Year2)`. Also replace narrative citations like `@Lanjouw2004` with `Lanjouw (2004)`.
4. **Hanging Bibliography Generator**: Read the compiled citation keys in the document. Retrieve and format their full reference strings in Springer-basic style (sorted alphabetically) and append them under the `# References` heading.
5. **Auto-Numbering Headings**: Track section counters (`h1_counter`, `h2_counter`). Prepend numbers to level 1 and level 2 headings dynamically (e.g., `1. Introduction`, `3.1 Data...`). Waiver special headings like `Abstract`, `References`.
6. **Figure Captioning**: Capture figure alt-text from image links (e.g., `![Caption](path){#label}`). Format the text, increment a figure counter, and place a bold label below the image (e.g., **Fig. 1** *CPC section distribution...*).
7. **ReportLab `Table` Layout**: Replace `Preformatted` table blocks. Parse markdown tables into 2D lists, convert cell strings into ReportLab `Paragraph` flowables (enabling text-wrapping), and render them with `TableStyle` enforcing:
   - LineAbove: thick black line.
   - LineBelow (header): thin black line.
   - LineBelow (table): thick black line.
   - Bold caption above the table (e.g., **Table 1** *Dataset characteristics...*).

### 3. Pipeline Integration
The renderer is called at the end of **Phase 9** (quality gates + render). In `paper_driver.py`'s phase 9 command block, we will replace the default or manual render steps with:
```bash
python3 render_qmd_reportlab.py paper_draft_v0.qmd paper_draft_v0.pdf
```
This ensures that `job_runner.extract_output()` receives a Springer-formatted `paper_draft_v0.pdf` that is >1000 bytes and matches the expected schema.

## C. Fix 2 — Review -> Revision Iteration Loop

### 1. Loop Structure in `paper_driver.py`
We will introduce a control loop in `paper_driver.py`'s `main()` function. This loop will execute after the initial paper compilation and review phases, running up to 2 rounds or until no P0 issues remain.

```python
    # 1. Run initial generation (phases 1-8) and check/render (phase 9)
    # 2. Run initial reviews
    for kind in ["review_mvp", "review_7dim"] + (["review_elite"] if elite else []):
        run_hermes(run_dir, kind, review_prompt(kind, contract, args.lane), args.model, provider, args.timeout)
    
    summary = compile_review.compile_reviews(run_dir, content_threshold=args.content_threshold, elite_required=elite)
    
    # --- Start Review-Revision Loop ---
    max_rounds = 2
    round_idx = 0
    p0_count = summary.get("p0_count", 0)
    
    while p0_count > 0 and round_idx < max_rounds:
        round_idx += 1
        print(f"--- Iteration Round {round_idx} Starting (p0={p0_count}) ---", flush=True)
        
        # A. Archive current files to preserve iteration history
        archive_dir = run_dir / f"history_round_{round_idx}"
        archive_dir.mkdir(parents=True, exist_ok=True)
        for f in ["paper_draft_v0.qmd", "paper_draft_v0.pdf", "mvp_check_report.md", "paper_review_report.md", "final_content_review_deterministic.json"]:
            src = run_dir / f
            if src.is_file():
                import shutil
                shutil.copy(src, archive_dir / f)
        
        # B. Construct the revision prompt feeding back specific errors
        problems = summary.get("problems", [])
        real_summary = load_real_summary()
        revision_prompt = build_revision_prompt(contract, args.lane, problems, real_summary)
        
        # C. Run revision generation (rewriting paper_draft_v0.qmd)
        rev_code = run_hermes(run_dir, f"phase8_revision_r{round_idx}", revision_prompt, args.model, provider, args.timeout)
        if rev_code != 0:
            print(f"Revision round {round_idx} failed during writing", flush=True)
            break
            
        # D. Re-run Quality Gates + Springer PDF Rendering
        gate_code = run_hermes(run_dir, f"phase9_revision_r{round_idx}", paper_prompt("phase9", contract, args.lane, real_summary), args.model, provider, args.timeout)
        if gate_code != 0:
            print(f"Revision round {round_idx} failed during rendering", flush=True)
            break
            
        # E. Re-run reviews
        for kind in ["review_mvp", "review_7dim"] + (["review_elite"] if elite else []):
            run_hermes(run_dir, f"{kind}_r{round_idx}", review_prompt(kind, contract, args.lane), args.model, provider, args.timeout)
            
        # F. Re-compile reviews to evaluate convergence
        summary = compile_review.compile_reviews(run_dir, content_threshold=args.content_threshold, elite_required=elite)
        p0_count = summary.get("p0_count", 0)
        print(f"--- Iteration Round {round_idx} Complete (new_p0={p0_count}) ---", flush=True)
        
    # The files remaining in the root run_dir represent the final iteration, preserving the contract.
```

### 2. Rewrite Prompt Design
To guide the weak model (`big-pickle`) effectively, the revision prompt must be highly directive, providing the exact context and grounding metrics to prevent the model from hallucinating or introducing new errors.

#### Revision Prompt Template:
```
Bounded task: revise the existing paper draft to resolve quality problems.
Inputs: paper_draft_v0.qmd, references.bib, figures/, tables/.

You must edit the existing paper draft (paper_draft_v0.qmd) to resolve the following list of problems identified in the previous version:

=== REVIEW PROBLEMS FEEDBACK ===
{problems_list_bullet_points}

=== VERBATIM REAL RESULTS GROUND TRUTH ===
Ensure all tables, figures, and text descriptions match these numbers exactly. Do NOT invent or round them differently:
{real_results_table_verbatim}

=== SPECIFIC DIRECTIVES FOR CRITICAL DEFECTS ===
1. For G2-001 (Temporal Holdout Contradiction):
   The dataset consists entirely of patents from the single filing year 2016. A split that trains on 2014-2018 and tests on 2020 is IMPOSSIBLE. You MUST:
   - Edit §3.3 (Evaluation Protocol) and §3.1 (Data) in paper_draft_v0.qmd.
   - Describe the evaluation protocol purely as a nested 5-fold cross-validation on 2016 patent applications.
   - Remove all training ranges (2014-2018) and holdout years (2020).
   - Reframe the "temporal holdout" language to state that cross-temporal validation was waived due to single-year cohort constraints.
2. For G1-001 (Task/Label Consistency):
   Change "9-class classification" to "7-class classification" across the text and table descriptions.
3. For G1-002 (fig_specs.json metadata match):
   Ensure that fig_specs.json and paper text both specify 5 classifiers (Logistic Regression, LinearSVC, Random Forest, Gradient Boosting, Multinomial Naive Bayes) across 7 CPC sections.
4. For G7-001 (Bonferroni correction inconsistency):
   Align the Bonferroni corrected significance threshold to alpha/10 = 0.005 consistently across text, tables, and figure specs.

Rules:
- Read the current paper_draft_v0.qmd from disk.
- Edit it to fix the problems above and write the updated contents back to paper_draft_v0.qmd.
- Do NOT truncate any sections or output a skeleton. The paper must remain a full-length, detailed manuscript (>3000 words).
```

### 3. Convergence & History Requirements
- **Convergence Condition**: The loop terminates early if `p0_count == 0` (indicating no desk reject risk), or when `round_idx == 2` (maximum limit of 2 revision rounds).
- **Final Emitted Artifacts**: The root `run_dir` contains the files of the final round (the last round executed). This ensures that `job_runner.py`'s `extract_output()` consumes the latest, most correct results and scores without modifying the runner.
- **Iteration History**: Copying files to `history_round_1/` and `history_round_2/` preserves intermediate states for debugging and auditing.

### 4. Resolving the `meets_threshold` Inconsistency
Currently, `job_runner.py` computes `meets_threshold` dynamically in `threshold_fields` based only on the score, whereas `compile_review.py` enforces both `score >= threshold` and `p0_count == 0`.
- **Recommendation**: Align `job_runner.py` with `compile_review.py` by editing `threshold_fields` in `job_runner.py` to check both conditions. It should extract the `no_p0` field from `gate_report.json` and combine it:
```python
    meets_threshold = bool(
        score_float is not None
        and threshold_float is not None
        and score_float >= threshold_float
        and no_p0_passed
    )
```

## E. Risks & Open Questions

1. **Weak Model Revision Failure**: The `big-pickle` model is weak and prone to hallucination. When revising the draft, it may resolve the P0 contradiction but accidentally truncate other parts of the paper, delete sections, or corrupt citation tags. 
   - *Mitigation*: We must include strong instructions in the prompt to prevent truncation and run mechanical word-count checks during compilation.
2. **BibTeX Parser Edge Cases**: A regex-based BibTeX parser might break on complex entries (e.g., corporate authors, special LaTeX characters, multiple-line fields).
   - *Mitigation*: Fall back gracefully to the citation key `[@key]` if formatting fails, rather than crashing the rendering script.
3. **Table Column-Width Auto-Sizing**: ReportLab tables can overlap page boundaries if columns are not auto-sized properly.
   - *Mitigation*: Explicitly calculate column widths based on the maximum cell content length or split widths proportionally.
4. **Owner Decision on `meets_threshold`**: Should we fail the job entirely if `p0_count > 0` even if the score is high? Aligning `job_runner` with `compile_review` enforces this, which will decrease the pass-rate of master runs but ensure higher overall quality. We recommend enforcing this.
